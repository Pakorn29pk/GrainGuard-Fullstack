# UIAudit · GrainGuard Overview

ตรวจหน้า Local และ Online ด้วย Chromium โดยล็อกอินบัญชีทดสอบโรงสี 6 Node และบัญชีเดโม 1 Node จากนั้นตรวจการส่งไฟล์ CSS จาก Pi4 และ HTTPS สาธารณะหลังติดตั้ง

| ด้านที่ตรวจ | คะแนนในขอบเขตงาน | ผล |
| --- | --- | --- |
| Accessibility | 3/4 | ใช้คีย์บอร์ดเลือกตัวกรองได้ทั้งสองช่องทาง สถานะตัวกรองอัปเดตผ่าน `aria-pressed` ปุ่มท้ายการ์ดบนจอเล็กมีขนาดขั้นต่ำ 44 × 44 พิกเซล |
| Performance | 4/4 | เปลี่ยน CSS อย่างเดียว ไม่มีไฟล์หรือ JavaScript ที่เบราว์เซอร์ต้องโหลดเพิ่ม |
| Responsive design | 3/4 | ทดสอบ 7 ขนาด ตั้งแต่ 360 × 800 ถึง 2560 × 1440 การ์ดกว้างเท่ากันระหว่างสองช่องทาง ไม่มีการเลื่อนแนวนอนหรือเนื้อหาในแนวตั้งถูกตัด |
| Theming | 3/4 | สลับภาษาไทย–อังกฤษและโหมดมืดบนจอ 360 พิกเซลได้ การปรับ CSS ใช้โครงสร้างและสีของธีมเดิม |
| Implementation integrity | 4/4 | UIAudit detector รายงาน 0 รายการใน CSS ที่แก้ ใช้เทมเพลตการ์ดเดิม ตรวจพบปุ่มตั้งค่าเครื่องเฉพาะ Local |

## ขนาดการ์ด Online ที่วัดได้

| ขนาดหน้าจอ | ก่อน | หลัง |
| --- | --- | --- |
| 1440 × 900 | 317 × 331 px | 317 × 308 px |
| 1920 × 1440 | 451 × 582 px | 419 × 414 px |
| 2560 × 1440 | 664 × 582 px | 419 × 414 px |

ที่ความกว้าง 1920 พิกเซล การ์ดหลังแก้สูง 414 พิกเซลเท่ากันทั้งจอสูง 1080 และ 1440 พิกเซล ตรวจแยกทั้ง Local และ Online

**P3** ที่หน้าจอกว้าง 768 พิกเซล แถวการ์ดแรกของ Local สูงกว่า Online 50 พิกเซล เพราะ Local มีปุ่มตั้งค่าเครื่องเพิ่มและต้องเผื่อพื้นที่เมื่อปุ่มขึ้นบรรทัดใหม่ ทั้งสองฝั่งยังเรียง 2 คอลัมน์และไม่มีเนื้อหาถูกตัด

ตรวจตัวกรองขาดข้อมูล กลับไปดูทุกเครื่อง เปิดรายละเอียดเครื่อง ดูการ์ดที่มี Alarm และเปิดบัญชีเดโม 1 Node ผ่านทั้งสองช่องทาง ข้อมูลเครื่องที่ใช้ทดสอบเป็นข้อมูลจำลอง

## ติดตั้งบน Pi4

Local และ Online บน Pi4 ส่ง CSS ตรงกับไฟล์ที่ตรวจแล้ว เว็บสาธารณะตอบ HTTP 200 และ SHA-256 ตรงกันทั้งสามทาง
